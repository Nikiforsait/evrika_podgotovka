# Эврика — как устроена база данных пользователей

## Коротко

База данных — это один файл `server/data/users.json` на сервере. Это список
пользователей: у каждого почта, имя, хэш пароля и весь прогресс по темам. Файл
ведёт небольшой сервер на Node.js (`server/index.ts`), он же раздаёт сам сайт.
Отдельная СУБД (MySQL, PostgreSQL) не нужна. Ученик входит с любого устройства,
а его прогресс подтягивается из аккаунта.

## Что хранится по каждому пользователю

| Поле | Что это | Пример |
|---|---|---|
| `id` | Внутренний номер пользователя | `3f9c1a7b2d4e5f60a1b2c3d4` |
| `email` | Почта в нижнем регистре, используется для входа | `masha@example.com` |
| `name` | Имя, которое показывается в приложении | `Маша` |
| `salt`, `hash` | Соль и хэш пароля. Сам пароль не хранится нигде | `a3f0…`, `9c2e…` |
| `createdAt` | Дата регистрации (мс с 1970 г.) | `1791563108449` |
| `tokens` | Активные сессии: на каждом устройстве свой токен входа | до 10 штук |
| `progress` | Прогресс: темы, попытки, карточки формул, дуэли, диагностики | см. ниже |

### Что внутри `progress`

Это снимок всех данных ученика, в тех же структурах, что и в приложении:

- **profile** — имя, XP, уровень, стрик, заморозки, активные дни, настройки,
  результат стартового теста (балл по шкале 19, разбивка по блокам, число прохождений), все
  прохождения полной диагностики (до 12 последних).
- **topics** — по каждому из 19 заданий: уровень освоения (0–1), рейтинг
  сложности, число попыток, прочитан ли разбор.
- **attempts** — каждая решённая задача: номер задания, уровень, результат
  (1, 0,5 или 0), ответ ученика, тип ошибки, дата.
- **cards** — состояние карточек формул для интервального повторения.
- **notes** — заметки об ошибках для личного справочника.
- **duels** — сыгранные дуэли и их результаты.

## Как проходит регистрация и вход

1. Ученик заполняет форму: почта, имя, пароль (не короче 8 символов, обязательно
   буквы и цифры).
2. Сайт отправляет данные на сервер (`POST /api/register`). Сервер проверяет,
   что такой почты ещё нет, вычисляет хэш пароля (PBKDF2‑SHA‑256, 100 000
   итераций, случайная соль) и добавляет запись в `users.json`.
3. Сервер выдаёт токен сессии (случайные 64 символа). Токен хранится в браузере
   ученика и отправляется с каждым запросом прогресса.
4. При входе (`POST /api/login`) сервер сверяет хэш и выдаёт новый токен.
   Неверная почта и неверный пароль дают одинаковый ответ, чтобы по ошибке нельзя
   было узнать, зарегистрирована ли почта. После 10 неверных попыток за 15 минут
   вход для этой почты и этого адреса временно блокируется.
5. Выход (`POST /api/logout`) удаляет токен этого устройства; остальные
   устройства продолжают работать.

## Как синхронизируется прогресс

- Приложение хранит прогресс в браузере (IndexedDB) и работает без интернета.
- При входе, затем каждые две минуты и при восстановлении сети сайт отправляет
  на сервер (`POST /api/sync`) всё, что изменилось с прошлой синхронизации, и
  получает изменения с других устройств.
- Правила слияния: решённые задачи и заметки только добавляются; XP, стрик и
  рекорды берутся по максимуму; остальное — по более поздней дате изменения.
  Так прогресс никогда не теряется, даже если ученик занимался с двух устройств
  по очереди.
- Если на одном устройстве входит другой ученик, локальные данные предыдущего
  стираются с устройства (на сервере они остаются).

## Безопасность

- Пароли не хранятся и не передаются в открытом виде никуда, кроме самой формы
  входа. В файле только хэш, восстановить пароль из него нельзя.
- Токен действует только для своего пользователя: подменить чужой `id` нельзя,
  сервер берёт его из токена.
- Размер запроса ограничен 2 МБ, число записей на одного ученика ограничено,
  поэтому один пользователь не может «раздуть» файл.
- Файл пишется атомарно (сначала во временный файл, затем переименование), так
  что сбой питания не повредит список.
- `users.json` не попадает в git и в архив проекта. Это персональные данные:
  делайте его резервные копии и ограничьте доступ к серверу.
- Сайт работает по HTTPS, если его поставить за обычный обратный прокси
  (nginx, Caddy) или на платформу с готовым сертификатом.

## Как посмотреть пользователей

Откройте `server/data/users.json` любым текстовым редактором: это читаемый JSON.
Для подсчёта или выгрузки в таблицу подойдёт любой JSON‑инструмент. Отдельной
админ‑панели пока нет; при необходимости её легко добавить поверх этого же файла.

## Как запустить

- Разработка: `npm run dev` — сайт и сервер аккаунтов (порт 8787) стартуют вместе.
- Продакшен: `npm run build`, затем `npm start` — один процесс раздаёт сайт и
  API на порту из переменной `PORT` (по умолчанию 8787). Путь к файлу
  пользователей задаётся переменной `DATA_FILE`.

## Ограничения и план на будущее

JSON‑файл удобен на старте: без установки СУБД, прозрачен, легко бэкапится.
Он рассчитан на сотни пользователей. При тысячах активных учеников файл будет
переписываться часто и целиком, поэтому тогда стоит перейти на PostgreSQL или
SQLite. Код к этому готов: вся работа с хранилищем сосредоточена в одном месте
(`server/index.ts`, функции `load` и `persist`), остальная логика
(`server/api.ts`) не меняется.
